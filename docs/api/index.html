POST /v1/entitlements/reload

Entitlements Reload. Tenant credential required.

Re-read ``ALES_ENTITLEMENTS`` / ``ALES_ENTITLEMENTS_FILE`` and invalidate decisions for tenants whose entries changed: their revocation epoch is bumped (conservative: every cached ALLOW of that tenant is re-evaluated) and an ``entitlements.reload`` record is appended to each such tenant's ledger. The document is process-wide, so this admin call may bump OTHER tenants' epochs when their entries changed; the response reveals only the caller's own tenant. A malformed document leaves the previous entitlements (and every epoch) untouched. Call it on EVERY replica: each holds its own in-memory copy.

POST /v1/outbox/reconcile

Outbox Reconcile. Tenant credential required.

Operator-triggered store reconciliation. The operator scans a downstream store (see ``scripts/ales_store_scan.py``) and posts the context ids it found. Returns ``tombstoned`` (present in the store although revoked: purge is owed or was missed, e.g. a cache data key whose reverse-index write never landed so the purge handler could not find it, with the outbox state of that object), ``untracked`` (ids this tenant never registered: orphans of a failed or crashed registration) and ``ok``.
