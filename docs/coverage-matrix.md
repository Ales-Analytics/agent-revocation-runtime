Notes:

- The table above is the report's rows verbatim. The report is generated by `python -m ales_conformance.report` and carries no generation timestamp, so the date of the run is not recorded here.
- `live store` rows appear only when that store was reachable when the report was generated. A re-run without Qdrant, pgvector or Redis reachable will drop those rows; that is not a failure of the adapters.
- `in-memory` means a process-local stand-in (DictRedis / InMemoryVectorBackend), not the production store.
- Enforcement contract (a-e): pre-revocation read allowed; post-revocation read blocked; blocked read carries a spec reason code; re-read after block stays blocked; a read from another source is unaffected. Optional physical-purge check (f) applies to adapters that own a store.
- Coverage caveat: a pass means the adapter's guarded read path enforces. Direct access to the underlying store bypasses the adapter and is not covered.
- The earlier version of this file listed every adapter as pending. That was stale against the conformance report and has been replaced.
