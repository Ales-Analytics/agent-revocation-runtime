MIGRATION RACE (read this):
  The server runs `alembic upgrade head` inside create_app() at every process start and, as of this version, has NO
  environment switch to skip it (ALES_SKIP_STARTUP_MIGRATIONS does not exist; the chart does not set it).
  Concurrent replicas starting against a database that is behind head can therefore race.
{{- if .Values.migrations.enabled }}
  Mitigation in this chart: a pre-install/pre-upgrade hook Job ("{{ include "ales.fullname" . }}-migrate") brings the
  schema to head first, so pod startup upgrades are no-ops. If that Job fails the release fails; inspect with
  `kubectl -n {{ .Release.Namespace }} logs job/{{ include "ales.fullname" . }}-migrate`.
{{- else }}
  WARNING: migrations.enabled=false. Run migrations out of band, or roll out with replicaCount=1 first
  (then scale up) whenever a release contains a schema change.
{{- end }}
  Schema changes must be backward compatible with the previous app version (rolling update runs both together).
